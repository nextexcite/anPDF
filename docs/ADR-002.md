# Rust runtime and contract generation

Status: accepted implementation direction; supersedes the earlier Node runtime proposal.

Rust owns the shared dispatcher, filesystem policy, CLI, optional loopback HTTP,
MCP stdio, and replaceable qpdf subprocess integration. Ordinary product use
requires neither Node nor a daemon. Initial platform target: Linux and macOS.
Other platforms fail explicitly until their filesystem/resource policy is qualified.

The canonical OpenAPI contract remains the sole operation/schema authority.
Pinned Cloudflare Forge 0.2.0 at
b8d74e2cbe41e4afaf2acaec2903add0bc11b116 remains mandatory build-time adoption.
Node/TypeScript are permitted only for upstream generation and qualification.
Handwritten Rust transport adapters are deliberate. They derive discovery and
runtime request/response validation from the owned contract, and are not
represented as generated code. Forge artifact qualification remains a release gate.

CLI and MCP use one configured workspace root; HTTP requires a startup root and
bearer credential. Every path in an operation is relative to that root.
Transformations reject encrypted, form-bearing, signed, and preservation-unknown
inputs (the shipped exception: `encryptPdf`/`decryptPdf` rewrite only password
protection). qpdf does structural work; rendering and signature trust are outside scope.

Public release requires a reviewed Forge artifact pin, reproducible generation,
platform/fixture/container qualification, dependency licenses, SBOM, and privacy review.
